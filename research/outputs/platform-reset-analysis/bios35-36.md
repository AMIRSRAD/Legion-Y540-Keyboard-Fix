# BIOS 35 and 36 static package comparison

2026-10-13. Original installers were never executed. Innoextract extracted their nested SFX archives; Windows tar extracted those archives. Existing isolated uefi-firmware 1.16 parsed firmware volumes; existing ACPICA iasl 20260408 disassembled the DSDT. Files were written only to analysis directories. No BIOS or keyboard image was changed or flashed.

## Identity and format

Input package hashes and nested executable hashes are in `bios35-36-hashes.json`. Each extracted BIOS.fd is 18,072,648 bytes and begins with a PE32+ executable header (PE offset 0xC8); it is not a raw standalone flash chip dump. Insyde container tags include `$_IFLASH_DRV_IMG`, `$_IFLASH_BIOSIMG`, `$_IFLASH_INI_IMG`, and BIOS certificate tags.

- BIOS 35 fd SHA-256: `13580df46ce2b5d54a7b6fdeef770634f7cd5bbf75650da9b6a1ae9f2ec6219f`.
- BIOS 36 fd SHA-256: `df9a58f2a2dda87d39cd510fb597b6e7e7d44dd947782bba0f09942231923db3`.
- BIOS-image container tag is at fd offset 0x12E9F8 in both; an Intel flash descriptor signature follows inside its payload.
- Ten bounded firmware volume candidates have valid header checksums in each image. Nested compression was expanded by the UEFI parser. Raw fd differences number 2,528,958 bytes; compressed-data churn makes that unsuitable as a count of changed functionality.

`bios35-36-inventory.json` preserves exact volume offsets, lengths, checksums, PE section descriptors, and string offsets. Extracted artifacts and scripts remain under `work/bios-reset-35-36`.

## ACPI result

Found 38 distinct checksum-valid DSDT/SSDT objects in each decompressed artifact set. Of those, 37 are byte-identical between 35 and 36. The sole changed table has OEM table ID `NvdPegTb`; its name suggests an NVIDIA PCIe table but that label alone is not proof of functional change. Inventory and provenance: `bios35-36-acpi-inventory.json`.

The 196,198-byte DSDT is byte-identical between 35 and 36, SHA-256 `1b97557dfc458b4872cedf0d2103f7d0e6cd43c34b556e379ff5d7ee65d9ccbd`. Its `HS09` device, corresponding in address to the failed internal USB port 9, has `_ADR=9`, `_UPC`, and `_PLD`; it has no local `_PS0`, `_PS3`, or `_RST` method in the examined DSDT body. This does not exclude root-controller, EC, SMM, or GPIO power control elsewhere.

The DSDT `_PTS` method has a conditional S3/S4/S5 path calling `SGOV(0x04070017, One)` when `PFLV==2`. No verified mapping ties this GPIO selector to keyboard power/reset. Do not translate it into a hardware write or patch. Parent analysis independently compared BIOS 45 and reports no HS09/_PTS/_WAK changes there; that conclusion belongs to the parent's separate comparison evidence.

The isolated DSDT disassembly emitted unresolved external/parent-prefix diagnostics for CNVW and PEG0 references, and conflicting ESPC/PSON external declarations. These are disassembly limitations, not independently established firmware defects. Static packaged tables may also be patched or conditionally installed at boot; they are not a live affected-machine ACPI dump.

## EC boundary

Both extracted platform.ini configurations set `[Region] BIOS=1, EC=0` and `[UpdateEC] Flag=0`. No separate EC payload filename was present in the extracted top-level archives. This proves only these packaged settings; BIOS firmware may perform EC work through other code.

The bounded ASCII signature search did not identify a verified IT8226/EC firmware region. One apparent `aGkb` hit was in compressed binary data and is discarded as a false positive. The EC payload, if embedded, remains unidentified. There is no evidence here that BIOS 36 supplies a keyboard power/reset repair, and no recommendation to flash it follows from this extraction.

## Reproducibility and limits

- `work/bios-reset-35-36/inspect.py`: PE/FV inventory and checksum validation.
- `work/bios-reset-35-36/dump_fvs.py`: decompress/dump each bounded firmware volume, preserving parser logs.
- `work/bios-reset-35-36/scan.py`: find checksum-valid ACPI tables and bounded string candidates.
- An isolated py7zr dependency directory was installed before tar support was confirmed; it was not used for extraction and did not alter the system Python environment.

This comparison rejects a simple 35-to-36 packaged ACPI keyboard-reset change hypothesis. It does not prove that BIOS versions behave identically in USB firmware, SMM, embedded-controller code, or platform configuration.
